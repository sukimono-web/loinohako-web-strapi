### 3.2 コア実装: `src/admin/vite.config.js`

Vite Plugin の `transformIndexHtml` フックで以下を HTML に注入する：

| 注入先 | 内容 | 効果 |
|--------|------|------|
| `<html>` | `lang="ja" translate="no" class="notranslate"` | HTML 標準の翻訳オプトアウト |
| `<head>` 末尾 | `<meta name="google" content="notranslate">` | Google Translate 用オプトアウト |

**冪等性**:
- 既存の `lang` / `translate` / `class` 属性がある場合は上書きしない（保持）
- `class` 属性に `notranslate` が既に含まれていれば追加しない
- `<meta name="google" content="notranslate">` が既存なら再挿入しない

### 3.3 設計書からの逸脱（重要・要把握）

実装中に発覚した点で設計書から外したポイント：

| 項目 | 設計書 | 実装 | 理由 |
|------|--------|------|------|
| モジュール形式 | ESM (`import`/`export`) | **CommonJS** (`require`/`module.exports`) | Strapi 5 の `vite.config.example.js` が CJS のため互換性優先 |
| 名前付き export | `export const disableAutoTranslate` | `module.exports.disableAutoTranslate = ...` 属性付与 | CJS 形式で named export を提供する慣用パターン |
| テストの import | `import { ... } from ...` | `createRequire` 経由で CJS module 読み込み | Vitest の ESM テストファイルから CJS 実装を呼ぶため |
| meta 二重挿入防止 | 暗黙的に冪等想定 | **明示的にチェック** | テスト作成中に冪等性違反を検出して修正（§3.4 参照） |
| テストケース数 | 6 | **7**（`translate="yes"` 既存時の保持を追加） | 冪等性カバレッジ向上 |

**設計書もこれに合わせて同期更新する必要があります（残タスク）。**

### 3.4 テスト駆動で見つけた早期不具合

実装直後の単体テスト実行で **冪等性テストが 1 件失敗**：

- 失敗内容: `transformIndexHtml` を 2 回適用すると `<meta name="google">` が重複挿入される
- 修正: `NOTRANSLATE_META_RE` で既存チェックを追加し、存在時はスキップ
- 学び: Vite は通常 `transformIndexHtml` を 1 回しか呼ばないが、他プラグインとの相互作用や HMR を考えると冪等性は重要

修正後の再実行: **7/7 全 pass**

## 4. テスト構成詳細

### 4.1 単体テスト（`tests/unit/disable-auto-translate.spec.js`）

| # | ケース | 検証内容 |
|---|------|---------|
| 1 | 属性のない `<html>` への付与 | `lang="ja"` / `translate="no"` / `class="notranslate"` が追加される |
| 2 | meta 挿入位置 | `</head>` の直前に挿入される |
| 3 | 既存 `lang` の保持 | `lang="en"` を `lang="ja"` で上書きしない |
| 4 | 既存 `class` への追加 | `class="foo"` → `class="foo notranslate"` |
| 5 | 既存 `notranslate` の保持 | `class="foo notranslate bar"` はそのまま |
| 6 | meta 二重挿入防止 | 2 回適用しても meta は 1 個 |
| 7 | 既存 `translate` の保持 | `translate="yes"` を上書きしない |

実行: `npm run test:unit`（数百ms）

### 4.2 ビルド成果物検証（`scripts/verify-notranslate.sh`）

3 シグナルを grep で検証：
1. `translate="no"` が存在
2. `class="...notranslate..."` が存在（`\bnotranslate\b` でワード境界マッチ）
3. `<meta name="google" content="notranslate">` が完全一致で存在

ビルド出力パスが Strapi バージョン依存のため、3 候補を順に試行：
- `dist/build/index.html`
- `build/index.html`
- `.strapi/client/index.html`

実行: `npm run build && npm run verify:notranslate`

### 4.3 自動化していない検証（手動必須）

| 観点 | 理由 |
|------|------|
| Chrome 翻訳エンジンの実挙動 | ヘッドレス Chrome で翻訳機能が起動しない／CDP API でも制御不可 |
| クロスブラウザ翻訳機能（Edge / Firefox） | ステージング検証で手動確認 |
| クライアント環境固有拡張の影響 | 個別環境差は再現困難。対照検証（クライアント側）で切り分け |

## 7. 既知の留意事項

### 7.1 ビルド出力パス（T09 で要確認）

`scripts/verify-notranslate.sh` の `CANDIDATES` 配列にある 3 パスのいずれにも `index.html` が見つからなければスクリプトは FAIL する。Strapi 5.15.0 環境ではどれかに該当するはずだが、Strapi のバージョンアップでパスが変わる可能性あり。失敗時は `find . -name index.html | grep -E '(build|client|dist)'` で実パスを確認し、スクリプトを更新する。

### 7.2 設計書と実装の乖離

§3.3 の通り、設計書は ESM 前提で書かれているが実装は CJS。レビュー前に設計書を同期更新するか、PR 本文で乖離を明示する必要あり。

### 7.3 仮説の確証は未取得

障害レポートのステータスは「主要因仮説あり・対照検証中」のまま。対照検証（T01〜T02）で翻訳 OFF でもクラッシュ再現する場合、本実装は無害だが根本解決にはならず、Strapi 5.x 本体起因（代替仮説 A）への対応が別途必要。

### 7.4 vitest の Vite CJS 警告

テスト実行時に以下の警告が出るが、機能的には問題なし：
```
The CJS build of Vite's Node API is deprecated.
```
これは vitest 自身が内部的に Vite を CJS で読み込んでいるため。将来 vitest が ESM 化すれば消える。

### 7.5 `.gitignore` の変更について

引き継ぎを可能にするため、`docs/*` 全体を ignore していた既存ルールに以下の例外を追加した：
- `!/docs/incidents`
- `!/docs/designs`
- `!/docs/plans`
- `!/docs/handover`

`docs/` 直下のアドホックなファイルは引き続き ignore される。チームのドキュメント運用方針と整合しなければ revert を検討。

## 9. 質問が出そうな点（FAQ）

**Q. なぜ `bootstrap()` ではなく Vite Plugin か？**
A. `bootstrap()` は React mount 後に呼ばれるため Chrome の翻訳評価（DOMContentLoaded 前後）に間に合わない可能性がある。HTML 静的注入なら確実。設計書 §3.2 参照。

**Q. なぜ全画面オプトアウトか？ 一部だけ無効化しないのか？**
A. 管理画面はもともと `locales: ['ja']` で日本語固定運用されており、ユーザーが意図的に翻訳すべきコンテンツがないため全画面で問題ない。設計書 §6 リスク#2 でクライアント側の前提確認を求めている。

**Q. テストは ESM で書いてるのに実装は CJS？**
A. Strapi 5 の Vite 設定が CJS 形式で書く慣習のため。Vitest はテストファイル単位で ESM/CJS 混在できる。`createRequire` で CJS module を読み込んでいる。

**Q. クライアント側で対照検証中に画面が直ってしまったら？**
A. 主要因が翻訳機能だった証拠になる。本実装はそれを恒久化するもので、副作用も小さいので継続マージ可。
